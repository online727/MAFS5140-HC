# Strategy Documentation

This document describes the currently active strategy implementation in `strategy.py`. The active `Strategy` class combines two sub-strategies:

- `MeanVarianceStrategy`: a shrinkage, long-only, constrained mean-variance optimizer.
- `MomentumStrategy`: a cross-sectional short-horizon momentum strategy with a relative-volume filter.

The final portfolio is a time-varying weighted combination of these two signals.

## 1. MeanVarianceStrategy

### Model Type

The mean-variance component is a shrinkage mean-variance optimization model. It is not a simple unconstrained Markowitz portfolio. It is a constrained quadratic optimization model with:

- sample expected return estimation;
- expected-return shrinkage toward zero;
- covariance shrinkage toward a diagonal covariance matrix;
- long-only constraints;
- no-leverage constraint;
- per-asset maximum weight constraint;
- a small ridge term for numerical stability.

The strategy solves the following optimization problem:

```text
maximize    mu_shrunk^T w - (gamma / 2) * w^T Sigma_shrunk w

subject to  w_i >= 0
            w_i <= max_weight_per_asset
            sum(w) <= 1
```

This is equivalent to choosing a portfolio that balances expected return against variance penalty. The risk-return tradeoff is controlled by `gamma`.

### Estimation Window

The model uses a rolling price window:

```python
lookback_period = 78 * 5
min_period = 78 * 5
```

Assuming 78 bars per trading day, this corresponds to 5 trading days of history. The strategy stores `lookback_period + 1` price observations, because returns are computed from price changes.

Before enough history is available, the strategy returns zero weights, meaning the portfolio stays fully in cash.

### Return Estimation

The price history is converted into simple percentage returns:

```python
returns = history_df.pct_change().dropna()
```

The sample expected return vector is:

```text
mu_hat = mean(returns)
```

Numerical issues such as NaN and infinite values are replaced with 0.

### Mean Shrinkage

The strategy shrinks sample expected returns toward zero:

```text
mu_target = 0
mu_shrunk = (1 - mean_shrinkage) * mu_hat + mean_shrinkage * mu_target
```

With the current parameter:

```python
mean_shrinkage = 0.2
```

the final expected return estimate is 80% sample mean and 20% zero target:

```text
mu_shrunk = 0.8 * mu_hat
```

This reduces the impact of noisy short-window return estimates. Since the lookback window is only 5 trading days, raw sample means can be unstable; shrinking them toward zero makes the optimizer less aggressive.

### Covariance Shrinkage

The sample covariance matrix is:

```text
Sigma_hat = cov(returns)
```

The shrinkage target is the diagonal covariance matrix:

```text
Sigma_target = diag(diag(Sigma_hat))
```

The final covariance estimate is:

```text
Sigma_shrunk = (1 - cov_shrinkage) * Sigma_hat + cov_shrinkage * Sigma_target
```

With the current parameter:

```python
cov_shrinkage = 0.2
```

the model keeps 80% of the full sample covariance matrix and blends in 20% of the diagonal-only covariance matrix.

This means the strategy still uses cross-asset covariance information, but partially reduces reliance on estimated correlations. The diagonal shrinkage target makes the covariance matrix more stable when correlations are noisy.

### Ridge Stabilization

The strategy adds a small ridge term to the covariance matrix:

```text
Sigma_shrunk = Sigma_shrunk + ridge * I
```

where:

```python
ridge = 1e-6
```

This improves numerical stability for the quadratic solver, especially when the covariance matrix is close to singular.

### Optimization and Constraints

The optimizer uses `qpsolvers.solve_qp` with the `osqp` solver. Internally, the maximization problem is converted into the standard quadratic programming minimization form:

```text
minimize    (1/2) w^T P w + q^T w
```

with:

```text
P = gamma * Sigma_shrunk
q = -mu_shrunk
```

The current risk aversion parameter is:

```python
gamma = 10.0
```

Higher `gamma` penalizes portfolio variance more strongly and usually produces more conservative allocations.

The constraints are implemented as:

```text
-w <= 0                         # long-only
 w <= max_weight_per_asset       # per-asset cap
 sum(w) <= 1                     # no leverage
```

The current per-asset cap is:

```python
max_weight_per_asset = 0.10
```

If the solver fails, the strategy returns zero weights. After solving, weights are clipped again to satisfy the per-asset bound, reindexed to match the input tickers, and normalized if the sum exceeds 1.

### Mean-Variance Signal Summary

The signal generated by `MeanVarianceStrategy` is directly the optimized target weight vector:

```text
w_mv = argmax mu_shrunk^T w - (gamma / 2) * w^T Sigma_shrunk w
```

It is a risk-adjusted allocation signal. Assets receive higher weights when they have better shrunk expected returns relative to their risk and covariance contribution, subject to the long-only, no-leverage, and per-asset-cap constraints.

## 2. MomentumStrategy

### Model Type

The momentum component is a cross-sectional momentum ranking strategy with a volume confirmation filter. It does not optimize a covariance matrix. Instead, it:

1. measures short-term price momentum over multiple windows;
2. standardizes those momentum values across assets;
3. adjusts the momentum signal by relative trading volume;
4. selects the top-scoring assets;
5. allocates capital across selected positive-score assets.

### Technical Indicators Used

The strategy uses the following indicators:

- Short-horizon price momentum over 6 bars.
- Short-horizon price momentum over 12 bars.
- Cross-sectional z-score normalization of momentum.
- Relative volume, defined as latest volume divided by recent average volume.
- Volume multiplier, capped and thresholded.
- Top-N cross-sectional ranking.

The current parameters are:

```python
momentum_windows = (6, 12)
volume_window = 78
min_relative_volume = 0.8
volume_cap = 2.0
top_selector = 10
max_weight = 0.1
```

### Price Momentum Signal

For each momentum window, the strategy calculates simple price return:

```text
raw_return_i(window) = latest_price_i / past_price_i(window) - 1
```

It computes this for both 6-bar and 12-bar windows.

Each raw return vector is converted into a cross-sectional z-score:

```text
z_i = (raw_return_i - mean(raw_return)) / std(raw_return)
```

If the cross-sectional standard deviation is zero or invalid, the z-score vector is replaced with zeros. Infinite and missing values are also replaced with zero.

The final momentum score is the average of the z-scores across the two windows:

```text
momentum_score_i = average(z_i_6bar, z_i_12bar)
```

This creates a relative momentum signal. An asset with a high score is outperforming the current universe over the short momentum windows.

### Relative Volume Signal

The strategy also calculates relative volume:

```text
relative_volume_i = latest_volume_i / average_volume_i
```

where `average_volume_i` is computed over the most recent available observations, up to `volume_window = 78`.

The relative volume value is then converted into a capped multiplier:

```text
volume_multiplier_i = clip(relative_volume_i, 0, volume_cap) / volume_cap
```

With:

```python
volume_cap = 2.0
```

a relative volume of 2.0 or higher maps to a multiplier of 1.0. Lower relative volume maps proportionally below 1.0.

The strategy also applies a minimum relative-volume threshold:

```text
if relative_volume_i < min_relative_volume:
    volume_multiplier_i = 0
```

With:

```python
min_relative_volume = 0.8
```

assets trading with less than 80% of their recent average volume receive no positive contribution from the volume-adjusted signal.

### Final Momentum Score

The raw combined score is:

```text
score_i = momentum_score_i * volume_multiplier_i
```

The implemented code then returns the negative of this score:

```python
return -scores.replace([np.inf, -np.inf], 0.0).fillna(0.0)
```

Therefore, the ranking logic in the current implementation selects assets with the largest values of:

```text
final_score_i = -momentum_score_i * volume_multiplier_i
```

In practical terms, because `_build_weights()` uses `nlargest()`, the implemented strategy currently favors assets with more negative volume-adjusted momentum scores, not the highest positive momentum scores. This makes the active implementation closer to a short-horizon reversal or contrarian selection rule, even though the class name and comments describe it as momentum-based.

### Asset Selection

The number of selected assets is controlled by `top_selector`.

Current value:

```python
top_selector = 10
```

Since this is greater than 1, the strategy selects up to 10 assets with the largest final scores.

The helper method `_selection_count()` also supports percentage selection if `top_selector < 1`. For example, `top_selector = 0.1` would select the top 10% of assets.

### Weight Construction

The strategy initializes all weights to zero. It then selects the top-scoring assets and keeps only positive selected scores:

```text
positive_scores = selected_scores[selected_scores > 0]
```

If positive selected scores exist, weights are proportional to those scores:

```text
w_i_raw = final_score_i / sum(final_score_positive)
```

If no selected positive scores exist, the code falls back to equal weighting among the selected assets. However, the function returns all-zero weights earlier if no score in the full universe is positive, so this equal-weight fallback is only reachable in limited edge cases.

Finally, each weight is capped:

```text
w_i = min(w_i_raw, max_weight)
```

with:

```python
max_weight = 0.1
```

The clipped weights are not rescaled upward after clipping. Therefore, if the cap reduces some allocations, the unused capital remains in cash.

### Momentum Signal Summary

The signal generated by `MomentumStrategy` is a sparse target weight vector:

```text
w_mom
```

Only selected assets can receive nonzero weights. The signal is based on:

- cross-sectional short-window price movement;
- relative liquidity confirmation through volume;
- top-N ranking;
- score-proportional allocation;
- a 10% per-asset cap.

Because of the sign inversion in `_build_scores()`, the current implemented signal selects high values of negative volume-adjusted momentum. This should be interpreted carefully when describing the strategy behavior.

## 3. Combined Strategy

### Structure

The active `Strategy` class combines the two sub-strategies:

```python
weights_mom = self.mom_strategy.step(current_market_data)
weights_mv = self.mean_variance_strategy.step(current_market_data)
```

It then blends the two weight vectors:

```python
weights = mul_mom * weights_mom + (1 - mul_mom) * weights_mv
```

where:

```python
initial_mul_mom = 1
final_mul_mom = 0.2
```

### Time-Varying Signal Weight

The momentum weight multiplier is:

```python
mul_mom = initial_mul_mom - (initial_mul_mom - final_mul_mom) * min(1.0, counter / (78*5))
```

Equivalently:

```text
mul_mom_t = 1.0 - 0.8 * min(1, t / 390)
```

because:

```text
78 * 5 = 390
```

This means:

- At the beginning, `mul_mom` is close to 1.0, so the portfolio is almost fully driven by `MomentumStrategy`.
- Over the first 390 steps, the momentum contribution linearly decays.
- After 390 steps, `mul_mom` reaches 0.2 and remains there.
- The mean-variance contribution correspondingly increases from 0.0 to 0.8.

The final combined portfolio is:

```text
w_final_t = mul_mom_t * w_mom_t + (1 - mul_mom_t) * w_mv_t
```

After the decay period:

```text
w_final_t = 0.2 * w_mom_t + 0.8 * w_mv_t
```

### Interpretation

The combined strategy gives more influence to the fast cross-sectional price-volume signal early in the backtest. As more data becomes available, the strategy shifts toward the mean-variance optimizer, which needs enough historical observations to estimate returns and covariance.

This structure also handles the warm-up behavior of the mean-variance component. During its initial estimation window, `MeanVarianceStrategy` returns zero weights. In that period, the combined portfolio is mostly or entirely determined by the momentum component. Once the mean-variance model has enough history, it starts contributing to the final allocation.

### Constraint Preservation

Both sub-strategies are designed to satisfy:

```text
w_i >= 0
sum(w) <= 1
```

The combined strategy is a convex combination of those two non-negative, no-leverage portfolios because `mul_mom` stays between 0.2 and 1.0. Therefore, the blended output should also remain long-only and no-leverage, assuming both sub-strategy outputs satisfy the same constraints.

## 4. Summary

The currently active strategy is a hybrid allocation model:

- The mean-variance leg is a shrinkage-constrained Markowitz-style optimizer using a 5-day return window, zero-mean shrinkage, diagonal covariance shrinkage, OSQP quadratic programming, long-only constraints, no leverage, and a 10% single-name cap.
- The momentum leg is a cross-sectional price-volume ranking model using 6-bar and 12-bar price movement, z-score normalization, relative-volume filtering, top-10 selection, score-proportional allocation, and a 10% single-name cap.
- The final strategy linearly blends the two legs, starting from a momentum-heavy allocation and decaying to a stable 20% momentum and 80% mean-variance mix after 390 steps.
